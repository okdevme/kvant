kvant accepts **any** object with `parse` and `encode` methods, including
[Zod](https://zod.dev) schemas. Pass them directly to kvant wherever a schema
is expected.

## Installation

```npm
npm install zod
```

## The golden rule: never throw

Zod's `.parse()` **throws** on invalid input. That is the opposite of the
kvant schema contract, where stored values are user-editable and invalid
input must degrade gracefully.

When passing a Zod schema to kvant, make it total: either cover every
possible input, or attach a fallback with [`.catch()`](https://zod.dev/api#catch).

<switch>
  <case react>
```ts twoslash
import * as z from 'zod'
import { useSearchParams } from 'kvant/react'

// ❌ Throws on ?price=abc
const [unsafePrice] = useSearchParams('price', z.coerce.number())

// ✅ Falls back to 0
const [priceWithDefault] = useSearchParams('price', z.coerce.number().catch(0))

// ✅ Falls back to undefined (kvant/schema's default behavior)
const [price] = useSearchParams('price', z.coerce.number().optional().catch(undefined))
```
  </case>

## Codecs

[Zod codecs](https://zod.dev/codecs) are bidirectional by design, which maps
naturally onto kvant's parse/encode contract without any intermediate layers:

<switch>
  <case react>
```ts twoslash
import * as z from 'zod'
import { useLocalStorage } from 'kvant/react'

// Stored as an ISO string, used as a Date
const dateCodec = z.codec(
  z.iso.datetime().optional().catch(undefined),
  z.date().optional(),
  {
    decode: iso => iso != null ? new Date(iso) : undefined,
    encode: date => date?.toISOString(),
  }
)

// [!code word:dateCodec]
const [lastVisit, setLastVisit] = useLocalStorage('last-visit', dateCodec)
```
  </case>
  <case vue>
```ts twoslash
import * as z from 'zod'
import { useLocalStorage } from 'kvant/vue'

// Stored as an ISO string, used as a Date

  z.iso.datetime().optional().catch(undefined),

    encode: date => date?.toISOString(),
  }
)

// [!code word:dateCodec]
const lastVisit = useLocalStorage('last-visit', dateCodec)
```
  </case>
</switch>

See [Zod docs](https://zod.dev/codecs#useful-codecs) for
more useful codecs (`base64ToBytes`, `stringToURL`, etc.). All of them work with
kvant as long as they can't throw on the inputs the desired interface can actually
contain.

## Mixing `kvant/schema` and Zod

The most practical setup: let [`kvant/schema`](./schema) handle the storage layer
(smart casting, defaults, clear-on-default) and pipe into Zod.

```ts twoslash
import * as kv from 'kvant/schema'
import * as z from 'zod'

const uriToEmail = kv.uriComponent().pipe(
  z.email().optional().catch(undefined)
)
```

[`.pipe(schema)`](./schema#pipe) and all other built-in `kvant/schema` wrappers and combinators
accept any `{ parse, encode }` object, not only kvant schemas.
The kvant side deals with the raw storage representation, and Zod
validates the typed result. Encoding runs in reverse through the same chain.
Be careful with this power!
