[nuqs](https://nuqs.dev) is the library that popularized type-safe URL query
state for React: `useQueryState` syncs a piece of state with a search param,
using [parsers](https://nuqs.dev/docs/parsers/built-in) to convert between strings and typed values.
kvant's API is heavily inspired by nuqs. If you've used it, the core loop (schema to hook to
URL as source of truth) will feel familiar.

<switch>

```ts twoslash tab="nuqs"
import { parseAsIndex, useQueryState } from 'nuqs'

const [page, setPage] = useQueryState('page', parseAsIndex.withDefault(0))
```

```ts twoslash tab="kvant"
import { useSearchParams } from 'kvant/react'
import * as kv from 'kvant/schema'
```

## Key differences

### Many interfaces, not only search params

nuqs syncs state with URL search params. kvant treats search params as one
of many key-value interfaces, all sharing one API:

|                  | nuqs | kvant                                       |
| ---------------- | ---- | ------------------------------------------- |
| Search Params    | ✅ `useQueryState`    | ✅ `useSearchParams` / `useRouteQuery` (Vue Router, Nuxt)    |
| Route Params     | —    | ✅ `useRouteParams` (Vue Router, Nuxt)        |
| Router Query     | —    | ✅ `useRouterQuery` (Next.js pages router)          |
| Local Storage   | —    | ✅ `useLocalStorage`         |
| Session Storage | —    | ✅ `useSessionStorage`                        |
| Cookies          | —    | ✅ `useCookies`                |
| Custom Adapters | Limited to search params, undocumented    | ✅ [Supported & documented](./custom-adapters) |

### Multiple framework families

nuqs is React-only (with [adapters](https://nuqs.dev/docs/adapters) for Next.js, React Router and other React-based frameworks).
kvant additionally supports **Vue, Vue Router, and Nuxt**
with idiomatic composables that return writable refs:

### Options live at binding time, not call time

In nuqs, you can pass options per `setState` call
(`setPage(2, { history: 'push' }){:ts}`). kvant doesn't allow this by design:
options are set when binding (hook call) or globally ([options providers](./quick-start#global-default-options),
[`defineKvantState`](./advanced-usage#definekvantstate) defaults).

kvant hooks mirror the framework's original state API as closely
as possible: React's `setState` doesn't take options, Vue's `ref.value ={:ts}`
can't take options, so kvant's setters don't either. One state API to
learn, no surprises when switching interfaces.

### Schemas instead of parsers

nuqs [parsers](https://nuqs.dev/docs/parsers/built-in) define `parse`/`serialize` (with `eq` for comparison). kvant
[schemas](./schema) define `parse`/`encode` and add a fluent, Zod-like API on top:
checks, transforms, defaults, structures, via the built-in
[`kvant/schema`](./schema.mdx) library. [Zod](./zod) and [other validation libraries](./custom-schema#adapting-other-schema-libraries)
slot in too.

## Migrating from nuqs?

The concepts map closely:

| nuqs | kvant |
| ---- | ----- |
| `useQueryState(key, parser){:ts}` | `useSearchParams(key, schema){:ts}` |
| `useQueryStates(keyMap){:ts}` | `useSearchParams(keyMap){:ts}` |
| parsers (`parseAsInteger`, ...) | schemas (`kv.int(){:ts}`, ...) |
| `parse` / `serialize` | `parse` / `encode` |
| `.withDefault(value){:ts}` | `.default(value){:ts}` |
| `clearOnDefault` | `.default(value, { clearOnDefault }){:ts}` |
